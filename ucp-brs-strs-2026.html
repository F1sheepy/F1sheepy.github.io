1.1业务目的

一句话说明为什么做轮腿平台：补复杂地形能力缺口，同时明确不做什么。

编号业务目的说明与业务价值衡量依据

细节与出处展开

本项目的业务目的，是在未来高烈度局部冲突与城市/室内作战中，为营连级合成部队补上一块当前装备体系缺的能力： 一个能够进入废墟、楼梯间、地下空间与室内死角，并把「看得见的」快速转化为「打得准的」的可消耗前沿节点。

1.1.1业务驱动：三个正在同时发生的变化

作战形态战场向非结构化空间下沉
城镇攻坚、地下设施清剿、山地隘口争夺成为主要作战样式。作战空间从「开阔地 + 装甲对抗」转向「建筑内部 + 废墟 + 地下」， 而现有履带式/轮式无人车在这些地形上的通过性、体积与噪声均不满足要求。
人员风险有人分队首入伤亡不可接受
城镇作战中首批进入建筑与废墟的分队暴露时间最长、伤亡率最高。指挥员的现实诉求是 「先让机器进去把人找出来」，而不是「让人先进去试探」。
作战体系杀伤链需要更短的闭环
分布式作战要求「传感器—决策者—射手」在同一时间尺度内闭环。当前班组级侦察与火力引导高度依赖人工口述与地图标注， 从发现目标到火力反应往往以「分钟」计，难以抓住时敏目标。

1.1.3明确不做的事（防止范围蔓延）

  • 不是要替代有人战车：平台定位是「伴随 + 前出」的耗材型节点，不承担正面装甲对抗与持续火力压制的主力角色。
  • 不是通用机器人平台：不追求全地形全任务的通用性，聚焦城镇/复杂地形下的侦察—指示—有限打击。
  • 不追求全自主交战：现行政策与伦理约束下，致命性打击保持「人在回路」，本项目不将全自主开火列为目标能力。

范围外有人战车与步兵班组的编制调整编制与战术运用由使用方决定，本项目提供编组运用的能力与约束输入。

1.3业务概况

一句话一条业务图景：内部研制与保障链，加上外部采办与运用链。

内部研制与保障链
装备总体研制单位（主承包商）：总体方案、系统集成、整车联调、样机试制与定型。
分系统配套供应商：动力与轮腿执行机构、伺服电机与减速器、感知传感器、导航定位、边缘计算单元、通信链路、任务载荷。
算法与模型提供方：目标识别、路径规划、协同决策模型，负责 OTA 迭代与数据闭环。
试验鉴定机构：环境试验、越障试验、靶场效能试验、定型评审。
批产与保障体系：总装、备件供应、维修与训练支持。
外部采办与运用链
军方采办部门：立项、预算、合同、验收、采购数量决策。
作战部队（营连级）：战术运用、训练、战场反馈。
体系指挥控制网络：任务下达、态势汇聚、授权管理。
友邻无人集群与有人战车：编组协同、目标交接、路权与频谱协调。
保障分队：补给、换电、抢修、回收。
约束方：频谱管理、网络安全保密、伦理与法规、试验鉴定。
被影响方：平民与非战斗人员、自然环境、公众舆论。
  • 内部链：需求方 → 总体单位 → 分系统与算法 → 试验鉴定 → 部队。
  • 外部链：采办立项 → 竞争择优 → 定型批产 → 配属运用 → 退役处置。
  • 两条链的交点是「可消耗性」与「算法可升级」两个业务判断。
细节与出处展开

业务概况描述相关业务领域内的主要分块与外部实体及其相互关系。本项目处于「装备研制采办链」与「作战运用链」的交汇点。

BUSINESS PICTURE / 一句话业务图景 主承包商向下整合供应链形成「一台可消耗的轮腿式无人作战平台」，向上通过体系接口接入「一张分布式杀伤网」， 最终在营连级分队手中形成「先看后打、少死人、打得快」的战术价值。链条上任何一个环节的标准不统一，价值都会在交付端打折。

3.3.3成本与风险模型

  • 成本结构：单机硬件（执行机构、感知、算力、电池、武器站接口）约占主要成本；试验与鉴定、算法开发、保障体系建设构成其余部分。

  • 主要风险：①足式步态长时可靠性不足 → 影响可用率；②关键件供货与自主可控 → 影响进度；③算法在真实城镇场景的识别泛化不足 → 影响 MOE-01/MOE-03；④合规审查不通过 → 影响列装。

5.1作战背景与战略意图

一句话三叠加的战场特征，把「人先进入」改成「机器先进入」。

定位可消耗节点
允许在高风险动作（首入、诱饵、抵近标定）中损失。这一定位直接决定了成本约束、模块化快换与「无人员营救负担」的战术用法。
定位体系传感器 + 末端指示器
既是「看得见的眼睛」，也是「标得准的手指」。侦察不是终点，把坐标交到火力单元手上才是。
定位人机混编的一员
与有人战车、步兵班、无人机同编，服从同一套指挥关系与 ROE，而不是「独立作战的机器人」。
  • 三大特征：空间复杂化、电磁白热化、人员零容忍。
  • 战略意图转变：从口头协同到数据协同，从人先进入到机器先进入。
  • 平台三重定位：可消耗节点、体系传感器与末端指示器、人机混编一员。
细节与出处展开

未来高烈度局部冲突与城市反恐作战中，战场呈现三个叠加特征：空间复杂化（城市废墟、室内空间、地下设施、山地隘口）、 电磁白热化（强干扰、GPS 拒止、链路劫持）、人员零容忍（政治与社会对伤亡的承受阈值极低）。

战略意图是清晰的：把「人先进入」改为「机器先进入」，把「口头协同」改为「数据协同」。 在此意图下，轮腿式无人作战平台不是一件孤立装备，而是分布式智能杀伤网中的一个可消耗、可重构的前沿边缘节点。 它的价值由「接入体系的程度」决定，而不是由单机性能决定。

  • 每种样式给出场景、价值与风险，差异主要在参与系统与平台角色。
细节与出处展开

样式 A城市盲区破障与首入侦察

场景建筑内部清剿
有人分队在建筑外安全区隐蔽，释放 2 台平台进入建筑。平台以足式爬楼梯、越废墟、穿门洞， 将实时视频、目标坐标与楼层平面回传；操作员依此判断房间占用、楼梯口威胁与撤退路线。
价值人员暴露前置替代
预期效果：人员进入前完成 90% 以上的必查点位侦察；入楼人员暴露时间下降一半以上。
风险：室内通信衰减、玻璃与镜面误检、楼梯塌陷导致平台失去机动能力。

样式 B伴随火力压制与诱饵引诱

场景沿街推进
平台伴随步兵推进，利用武器站实施压制射击；或前出充当「诱饵」，迫使敌方火力点暴露， 由后方无人机或迫击炮实施精确打击。诱饵用法要求平台具备快速机动与低特征。
价值以耗材换情报
预期效果：敌方火力点暴露时间缩短，被引导打击概率提升。
风险：诱饵用法与被击毁概率高度相关，必须接受「有去无回」；须保证战损数据可回收或自毁。

样式 C拒止环境组网中继

场景强电磁干扰
敌方实施强干扰导致分队通信中断时，平台自主机动至高处或关键节点，作为微型基站搭建局部自组网， 维持分队的「数据生命线」，并为无人机提供中继。
价值体系抗毁重构
预期效果：局部链路中断后 60 s 内恢复连通，杀伤网不因单节点失效而整体瘫痪。
风险：中继阵位本身成为高价值目标；需在中继收益与被发现风险间取得平衡。

样式 D目标标定与火力引导

场景远程火力支援
平台在抵近位置观察目标，为迫击炮、巡飞弹或远程火炮提供末端标定与射击修正； 打击后持续观察并回报毁伤评估，决定是否补射。
价值缩短杀伤链
预期效果：发现到射击指令 ≤ 90 s，首轮命中率提升，弹药消耗下降。
风险：平台暴露时长增加；位置与阵位需在抵近与生存之间权衡。

样式 E跨域集群协同（与无人机、无人车编组）

场景空地一体
无人机提供俯视全局与目标指示，平台提供地面近距细节与室内信息；两者数据在平台边缘或上级节点融合， 形成「空地互补」的目标图像，并按优先级分配目标与频谱。
价值能力互补
预期效果：目标确认效率提升，虚警下降；避免己方装备互撞与频谱互扰。
风险：协同协议不一致、时延不同步、目标重复分配。

5.6体系角色

一句话平台在体系中是节点：进四条链路，任一链路断开都可重构。

链路 1侦察链
无人机（俯视）→ 平台（近距/室内）→ 指挥节点（态势融合）→ 分队长（判断）。平台是「最后一公里」的传感器，弥补空中视角被建筑遮挡的盲区。
链路 2打击链
平台（标定）→ 指挥节点（授权）→ 火力单元（迫击炮/巡飞弹/无人机）→ 平台（毁伤评估）→ 指挥节点（补射决策）。闭环中任何一环断裂，全链失效。
链路 3保障链
前沿补给点（能量/弹药）→ 平台（执行）→ 维修分队（模块更换）→ 后方基地（备件/算法）。保障链的效率直接决定出动率。
链路 4约束链
ROE 与授权链（法律）→ 火控逻辑（系统）→ 记录与审查（事后）。约束链保证「能打」不越界为「乱打」。
  • 四条价值链路：侦察链、打击链、保障链、约束链。
  • 多对多关系：一台平台可同时服务多个火力单元与情报用户。
  • 可插拔与可重构是体系角色的核心，需求对应入网≤3min、重构≤60s。

TR-01复杂地形隐蔽抵近与快速突防最高优先级

需求陈述：平台需具备在铺装路面高速机动，并在城市废墟、楼梯、壕沟等非结构化地形中自主越障通行的能力， 全程支持纯电静音模式，以支持隐蔽侦察与穿插任务。

量化判据：轮式最大速度 ≥ 10 km/h；足式越障高度 ≥ 0.25 m；可攀爬 ≤ 35° 斜坡与标准楼梯；跨越壕沟 ≥ 0.4 m； 轮足模式切换 ≤ 30 s；静音模式 10 m 处噪声 ≤ 65 dB(A)。

支撑关系：支撑任务层「隐蔽抵近侦察」；满足一线班组（No.1）的快速投送诉求与自然环境（No.19）的低噪声约束。

架构落点：轮腿复合移动系统 → 轮驱/转向、腿部摆动作动、悬架与减震子系统。

TR-02目标多维侦察与末端精准标定最高优先级

需求陈述：搭载多光谱光电载荷，实现对敌方人员、车辆、工事的自动探测、识别与持续跟踪； 具备前端边缘计算能力，直接解算目标高精度坐标并生成打击引导数据。

量化判据：1 km 内目标定位 CEP ≤ 5 m；激光指示偏移 ≤ 1 m @ 2 km；识别置信度 ≥ 0.9 才可作为「确认目标」上报， 低于阈值一律标注「疑似」；目标数据格式须符合体系报文标准。

支撑关系：支撑任务层「目标精确定位与引导」；满足体系指挥网络（No.5）对杀伤链闭环的时效诉求。

架构落点：智能感知与导航系统 → 目标探测与识别、定位与建图子系统；任务计算子系统。

TR-03载荷快换与有限自主伴随打击最高优先级

需求陈述：采用标准化接口，支持侦察、轻武器、电子战等任务载荷的快速互换。在有人班组伴随作战时， 可在人工授权下（或特定规则下自主）对突发高价值目标实施短停射击或压制。

量化判据：载荷更换 ≤ 10 min（2 人，无专用工具）；行进间射击平台姿态恢复 ≤ 1.5 s； 授权链路端到端时延 ≤ 500 ms；未授权时击发电路物理断开。

支撑关系：支撑任务层「自主伴随打击」；满足武器供应商（No.10）接口标准化与有人战车乘员（No.4）的火力支援诉求。

架构落点：作战载荷与武器管理系统 → 武器站伺服、射击控制与后坐管理、载荷快换接口。

TR-04通信拒止环境下的弹性网络中继高优先级

需求陈述：当战场通信链路受阻或前线编队失联时，平台能充当移动的边缘通信节点，自主前出或占位， 建立自组网中继链路，恢复局部杀伤网的数据连通。

量化判据：中继建立 ≤ 60 s；单跳覆盖 ≥ 3 km（视距）/ ≥ 500 m（建筑遮蔽）；同时中继 ≥ 2 路数据流。

支撑关系：支撑任务层「体系节点中继」；满足体系指挥网络（No.5）与友军集群（No.3）的抗毁重构诉求。

架构落点：指挥控制与通信系统 → 战术通信子系统、自组网电台模块。

TR-05体系互操作与即插即用接入最高优先级

需求陈述：必须遵循全军通用的数据链协议与态势图标准。交付后，无需更改体系代码即可实现「即插即用」式入网， 接受体系任务式指挥（Mission Command）。

量化判据：入网 ≤ 3 min；协议符合性测试零不符合项；报文丢包率 ≤ 1%；态势上报周期 ≤ 2 s。

支撑关系：满足体系指挥网络（No.5）、采办鉴定局（No.13）的强合规性约束。

架构落点：指挥控制与通信系统 → 体系数据链接口板、协同接口子系统。

TR-06人机混编协同与责任可追溯最高优先级

部署概念

支持概念

弃置概念
退役前完成脱密审查与数据销毁（含密钥模块物理自毁）；电池按危废回收；复合材料标识回收； 战损遗弃前须触发远程擦除，防止技术泄露。
  • 采办：总体单位牵头 + 分系统竞争择优 + 算法按版本服务交付。
  • 部署：随车或机降吊运，出箱到配属 ≤15min（2 人）。
  • 支持：三级体系，前线只换不修、不依赖专用工具。
  • 弃置：脱密审查 + 数据销毁 + 密钥模块物理自毁。

1.5.4三类经典分析的决定性结论

PRIORITY CONFLICTS / 相关方诉求的正面冲突 本项目存在三组硬冲突，必须在需求中显式裁决，而不能含糊处理：
① 可消耗性 vs 高生存性：班组希望「便宜到敢丢」，使用方希望「打不掉」；裁决原则是分任务阶段——侦察阶段保生存，诱饵阶段认损失。
② 低特征 vs 高性能：低红外/低噪声与高算力散热、大功率通信互相矛盾；裁决原则是分模式——静默模式降性能，交战模式放开。
③ 自主性 vs 合规性：算法越自主越高效，但授权链要求人在回路；裁决原则是「自主止于识别与建议」。

6.1.6运行约束

一句话能耗、安全、通信、人因四类约束，是运行概念不能越的边界。

能耗运行约束
足式攀爬时电机峰值功耗大，BMS 优先保障动力电，适当降低非核心传感器（如声学定位）的刷新率； 低电量阈值触发「保底分配」：定位 > 通信 > 机动 > 感知 > 打击。静默模式下主动探测关闭。
安全运行约束
开火瞬间须通过地理围栏（Geofencing）与射击安全扇区双重校验，确认自身及射击扇区内无友军； 否则击发电路物理断开。近距离人员闯入时执行「绝对防御」：避让、停机、退回，严禁开火。
通信运行约束
双链路冗余（自组网 + 卫通/蜂窝备份），按链路质量自动切换；失联后先静默、再返航； 中继模式下须评估阵位暴露风险，避免长期驻留高价值位置。
人因运行约束
单机操作员可同时监督 ≥ 2 台；紧急接管一级可达；界面须展示「为什么这么判断」， 避免操作员盲信算法；关键动作需二次确认，防止误触。
  • 能耗：BMS 保底分配，静默模式关闭主动探测，保底顺序写入降级策略。
  • 安全：围栏 + 扇区双校验，近距闯入绝对防御，优先于任务完成。
  • 通信：双链路冗余，失联先静默再返航；人因：单操作员监督 ≥2 台，关键动作二次确认。

R.1评审流程六步

一句话评审不是通读：出文档、提 RID、做决策、入基线六步。

① 制定并发布评审计划
确定评审人员（客户、需求拥有者、系统工程师、供应商、方案团队），确保覆盖全部相关方类型；即便不能出席，其观点也必须被处理。
② 出具相关文档
评审前至少两周完成基线并分发；提供检查单与评审指南，聚焦关键领域而非通读全文。
③ 接收并分析变更请求
鼓励会前提交变更请求（RID），便于分组、理解意图、评估影响。
④ 执行评审
会议目的是做决策而非通读文档：逐条接受/拒绝变更请求，记录行动项与决策依据。
⑤ 实现批准的变更
会议后更新规格与文档，把批准变更并入基线。
⑥ 结束评审
所有接受变更并入更新基线；备忘录显示每个请求状态与建议；后续变更走正式变更控制。
  • 六步：制定发布计划 → 文档提前两周出基线 → 提交 RID → 评审做决策 → 实现批准变更 → 结束入基线。
  • 关键动作是「做决策而非通读」：评审必须产出裁决与签字。
  • 评审通过后文档进入基线，任何后续变更走 RID 流程。
